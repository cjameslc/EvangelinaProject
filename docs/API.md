# API Reference

> Part of the [Evangelina's Staycation documentation](README.md).

76 route files under `src/app/api/`, generated by inspecting every file directly (method exports + auth check present in each). "Staff (any)" means `requireUser()` with no role restriction — authenticated staff of any role, with row/unit-level scoping enforced separately inside the handler. Where a handler used `getCurrentUser()` + an `rbac.ts` helper instead of `requireUser([...])`, the effective role restriction is noted the same way.

## Auth

| Route | Methods | Auth | Purpose |
|---|---|---|---|
| `/api/auth/[...nextauth]` | GET, POST | Public | NextAuth's own handler — staff login/session/logout |
| `/api/guest/auth/request-link` | POST | Public (rate-limited by IP + email) | Sends a guest a magic sign-in link |
| `/api/guest/auth/verify` | GET | Public (token in URL) | Consumes the magic-link token, mints a guest session |
| `/api/guest/auth/verify-confirmation` | POST | Public (rate-limited) | Signs a guest in with email + booking confirmation number — see [Booking.md](Booking.md#confirmation-number-validity) for the expiry rules enforced here |
| `/api/guest/auth/signout` | POST | Public | Clears the guest session cookie |

## Request/response conventions

- All request bodies are validated with **Zod** (`src/lib/validation.ts`); a validation failure returns `400` with `{ error: "..." }`.
- Auth failures return `401` (not signed in) or `403` (signed in, wrong role/scope) as a plain `Response`, not JSON, in most handlers — check `res.ok` rather than parsing JSON on those paths.
- Ownership/not-found failures on guest-facing routes return a **generic** message (e.g. "That booking ID doesn't match your active stay") regardless of which specific check failed, to avoid leaking which part of a guess was wrong (email exists? code right? stay expired?) — see [Security.md](Security.md#no-enumeration-on-guest-auth-endpoints).
- Rate-limited routes return `429` with `{ error: "Too many requests..." }`; rate limiting is in-memory per server instance (`src/lib/rateLimit.ts`) — best-effort, not a hard guarantee across Vercel's multiple serverless instances.
- Every state-changing staff route calls `logAudit(userId, action, entity, entityId, meta)` — visible on `/auditor` and via `GET /api/audit`.
