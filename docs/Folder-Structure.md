# Folder Structure

> Part of the [Evangelina's Staycation documentation](README.md).

This reflects the actual repository layout as of this writing. Generated by inspecting the codebase directly — not aspirational.

## Top level

```
evangelinas-staycation/
├── docs/                  This documentation set
├── prisma/
│   ├── schema.prisma      Full database schema (26 models) — see Database.md
│   └── seed.ts            Demo data seeder (npm run db:seed)
├── public/                Static assets — gallery photos, PWA manifest/icons, sw.js
├── src/
│   ├── app/                Next.js App Router — pages + API routes
│   ├── components/         React components, grouped by feature area
│   ├── lib/                 Business logic, services, utilities (no JSX)
│   └── types/               Shared TypeScript types
├── .env.example            Template env file — see Configuration.md (NOTE: stale, see below)
├── docker-compose.yml       Local Postgres container — NOT USED (see note below)
├── next.config.mjs          Security headers, image config
├── vercel.json               Cron schedule (Airbnb iCal sync)
├── package.json
└── tsconfig.json
```

> **Known inaccuracies in root-level files**, found while writing this documentation and left as-is pending a decision to update or delete them:
> - `docker-compose.yml` spins up a local **Postgres** container. The app's actual database is **Turso (libSQL/SQLite)**, connected directly via `DATABASE_URL`/`TURSO_AUTH_TOKEN` — no local Postgres container is used anywhere in the current setup. This file appears to be a leftover from an earlier version of the project.
> - The root `README.md` (not this `/docs` set) still describes a Neon/Postgres setup, a 5-role system with no Guest Portal, and other details that predate most of the current feature set. It has **not** been rewritten as part of this documentation pass — see [Troubleshooting.md](Troubleshooting.md) for the discrepancy and [Maintenance.md](Maintenance.md) for the recommendation to replace it with a short pointer into `/docs`.

## `src/app/` — routes

Next.js App Router: a folder = a URL segment, `page.tsx` = a rendered page, `route.ts` = an API endpoint. `[id]` / `[bookingId]` / `[category]` / `[token]` / `[format]` folders are dynamic segments.

### Staff pages (session-protected by `src/middleware.ts`)

| Path | Purpose |
|---|---|
| `/dashboard` | Financial dashboard — revenue, occupancy, payroll, attention cards |
| `/analytics` | Deeper reporting (bookings, revenue, occupancy, staff, forecast) |
| `/bookings` | Booking list/agenda, create/edit/cancel/delete, Excel import |
| `/calendar` | Per-unit occupancy calendar |
| `/housekeeping` | Cleaning checklist, unit status, stock counts, bills |
| `/auditor` | Read-only ledger + audit trail + quality findings |
| `/admin` | Units, Users & roles, Housekeeping checklist config, Settings |
| `/earnings` | Staff's own pay/commission view ("My Earnings") |
| `/account`, `/profile`, `/change-password`, `/notifications`, `/login` | Account/session pages |

### Guest-facing pages (public or guest-session-protected)

| Path | Purpose |
|---|---|
| `/` | Digital Guidebook hub (also the staff-in-"Travel Mode" landing page) |
| `/book` | Guest self-service booking flow |
| `/guest-login` | Passwordless guest sign-in (magic link or confirmation number) |
| `/my-bookings`, `/my-bookings/[id]` | Guest's booking history and per-booking Guidebook + payment hub |
| `/guide/*` | Digital Guidebook pages — welcome, wifi, check-in, check-out, amenities, house-manual, gallery, location, nearby/[category], reviews, faqs, contact, emergency, feedback/[bookingId] |
| `/listing/[id]` | Public per-unit listing page |

### API routes — `src/app/api/`

76 route files as of this writing, grouped by domain: `bookings/*`, `guest/*` (guest-facing, separate auth), `housekeeping/*`, `units/*`, `users/*`, `employees/*`, `ical/*` (Airbnb sync), `places/*` (Google Places), `auth/[...nextauth]`, `messenger/webhook`, plus single-purpose routes (`settings`, `audit`, `dashboard/insight`, `leaderboard`, `my-earnings`, `payroll-payments`, `weekly-expenses/*`, `coupons/*`, `feedback/*`, `expense-requests/*`, `auditor-findings/*`, `employee-achievements/*`). Full inventory with method/auth/purpose in [API.md](API.md).
